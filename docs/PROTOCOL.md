# 实验协议（PROTOCOL）

> 这份文件写的是**事先定好的规则**：跑什么、跑多少、用什么判据选模型、什么情况算失败。
> 目的是让"结论"不是跑完看着图挑出来的。所有阈值都在 `config.py` 里，改了就记在这里。

## 0. 一句话

在 pathmnist 上扫 (N, E) 网格 → 每点测记忆率 M → 用三个候选律拟合 M(N,E) →
按预先声明的判据选一个 → 反解安全早停 E*(N, ε) → 用四种停训策略验证它真的更安全/更省。

## 1. 数据

| 用途 | 数据集 | 训练/验证/测试 | 备注 |
|---|---|---|---|
| 主实验 | pathmnist | 89,996 / 10,004 / 7,180 | 9 类结直肠病理，彩色 |
| 跨数据集 1 | bloodmnist | 11,959 / 1,712 / 3,421 | 8 类血细胞，彩色；**有 5 张完全重复 + 4 张近似**（已在 τ 校准中剔除） |
| 跨数据集 2 | pneumoniamnist | 4,708 / 524 / 624 | 2 类胸片，**灰度**（复制 3 通道） |
| 仅调试 | 上述 28px 版本 | — | 见 NOTES 的限制说明 |

- **嵌套子集**：`train_subset_indices` 用固定 `rng(1000+seed)` 的排列前缀，
  所以 N=250 ⊂ N=500 ⊂ … ⊂ N=4000。保证不同 N 的差异不是"换了哪批图"。
- **参照集**（校准 τ 用）：官方 test 前 2000 张，**永不参与训练**。
- 训练集/参照集之间先用 `tools/check_leak.py` 查重（md5 + 8×8 缩略图余弦）。

## 2. 主网格：等步数预算

记忆化发生在**优化步**这个尺度上，所以每档 N 给相同步数预算 `STEP_BUDGET = 20000`
（batch=64 → 每 epoch 64 步），epoch 数按 N 反比：

| N | epoch 上限 | ckpt 间隔 | 测量点数 | 说明 |
|---|---|---|---|---|
| 250 | 5125 | 160 | 32 (+ 早期间隔 25 的 43 个点) | 最长的曲线 |
| 500 | 2550 | 80 | 32 | |
| 1000 | 1275 | 40 | 32 | |
| 2000 | 650 | 20 | 32 | |
| 4000 | 325 | 10 | 32 | 最短的曲线 |

- 每个 run 约 15–30 min（28px、bf16、RTX 5070 Laptop 8 GB）。
- **主网格 = 5 N × 3 seed = 15 个 run**，队列按 seed 优先（先跑完 seed 1 的五档）。
- 每个 ckpt 采 512 张样本（DDIM 50 步、fp32）→ `cache/samples/{run}/e{E:04d}.npy`。
- ckpt 只留最近 4 个（fp16，26 MB/个）；**样本永久保留**，评分只依赖样本。

## 3. 测量

对每个 (N, seed, E)：

1. DINOv2 ViT-S/14 特征（384 维，resize 224）→ 训练集上拟合**截断白化**
   （`k = max(32, min(384, N//2))`，收缩 1e-3）。
2. 生成样本到训练 bank 的最大余弦 `sim`。
3. `M = mean(sim >= τ)`，`τ` = 参照集最大余弦的 99.5 百分位（每个 N 单独校准，FPR=0.5%）。
4. 同时记录 `sim_mean / sim_p95 / sim_max / n_leak_dropped / encoder`。
5. FID：每 4 个测量点算一次（inception_v3，real 侧统计量缓存）。
6. 另报固定阈值（0.5/0.6/0.7）下的 M，做阈值敏感性分析。

**编码器一致性是硬约束**：CSV 的 `encoder` 列一旦与当前编码器不符，`score_run` 直接拒写。
（因为实测 dinov2_s → τ=0.6721、resnet50 → τ=0.8203，混用会把 M 从 7.8% 变成 0。）

## 4. 候选律与选型判据（预先声明，防止事后挑好看的）

```
L1 拉伸指数   M = Minf·(1 - exp(-(E/E50)^β)),  E50 = c·N^γ
L2 Hill      M = Minf·E^h/(E^h + K^h),        K   = c·N^γ
L3 双时间尺度  M = Minf·Φ((E - τ(N))/w),       τ   = a·N^γ
```

拟合在 `log10(M + 1e-4)` 空间做最小二乘（小 M 区间才是安全边界），多起点避免卡在 γ 的假解。

**选型判据**（按顺序）：
1. AICc 最小；
2. 留一 N 交叉验证（用 4 个 N 拟合、预测第 5 个 N）的平均 R² 最大；
3. 参数能讲出临床含义（E50 随 N 的幂律指数 γ 是否有物理意义）。

**验收线**（写进论文的）：
- 样本内 `R²_log ≥ 0.9`；
- 留一 N 的 `R² ≥ 0.8`；
- 主图：横轴 `E/N^γ`（或 `E·N`，即"每张图被看的遍数"）时，5 条 N 曲线塌缩成一条。

合成数据自检（`build/test_law.py`）已证明这套判据能工作：
真值 γ=1.0 被复原为 0.985，L1 的 LOO R²=0.91，而 L2 只有 0.42、L3 直接负。

## 5. 安全早停

- 定义：给定可接受记忆率 ε（主报 ε=0.01，附 0.05/0.10），求最小 E 使 M(N,E) ≤ ε 对**所有 E' > E** 成立。
- 反解：在选定律上用 `brentq` 求 `M(E)=ε` 的根。
- 输出：`E*(N, ε)` 表 + `E*/N^γ` 近似常数这一条（若成立，就是"每张图看多少遍才安全"的普适常数）。

## 6. 四种停训策略（基线对比）

| 策略 | 规则 | 角色 |
|---|---|---|
| A 固定跑满 | 跑满预算 | PPT 里的"常规训练"，最不安全 |
| B FID 平台早停 | FID 连续 3 点改善 < 1% 就停 | **最该打赢的对手**：只看生成质量，不管隐私 |
| C 开环律 E*(N,ε) | 用拟合出的律直接算停点（不测 M） | 我们的方法（免测量） |
| D 闭环在线测 M | 每 25 epoch 测 M，超 ε 就回滚上一个 ckpt | 我们的方法（最安全，但要多花测量成本） |

评价指标：停训时的 epoch 数、省下的算力比例、停点处的 M、停点处的 FID、违约率
（M 超过 ε 的 run 占比）。判据：**C/D 的违约率应显著低于 A/B，且 FID 不比 B 差**。

## 7. 失败与降级

- 拟合 R² 不达标 → 先查度量（τ 是否被泄漏抬高、样本数够不够），再考虑加测量点，**不换律凑 R²**。
- 时间不够 → 按 `PLAN.md` 的降级阶梯：先砍 seed（3→1），再砍 N_max（4000→2000），再砍 E_max。
- 任何"手动改过阈值/参数"的实验，必须在 `docs/NOTES.md` 记一笔，禁止事后静默调参。
## 8. 设计修订 R1：大 N 改用「深度档」预算（2026-10-30）

**触发**：等步数主网格（每档 2e4 步）跑完后，N=2000 / N=4000 的 66 个测量点**全部 M=0**（sim_max 最高 0.63/0.64，仍低于 τ≈0.64/0.66），只有 N=250/500/1000 三档有可测的上升段。留一 N 外推检验因此崩掉（LOO R² 0.30–0.44，六种律形式都过不了预声明线 0.8）。

**判断**：瓶颈是**数据覆盖**，不是律的形式。在等步数预算下，每张图被见到的次数 N_steps/N 相同，但大 N 的记忆化起点在步数坐标上更晚（τ_mem ∝ N），所以固定的步数预算会恰好在大 N 上停在"还没开始背"的区间。

**修订**：对 N=1000/2000/4000 追加**深度档**预算，让每个 N 的 M 都进入可测区间（目标 M≈0.05–0.2），预算按「M=0.02 所需步数 ∝ N^1.3」外推：

| N | 步数预算 | epoch | ckpt_every | 依据 |
|---|---------|-------|-----------|------|
| 1000 | 3.75e4 | 2400 | 75 | 实测 M=0.02 在 ~1.0e4 步，×3.5 留足上升段 |
| 2000 | 9.0e4 | 2900 | 90 | 由 N=1000 按 N^1.3 外推 → 2.5e4 步，×3.5 |
| 4000 | 8.75e4 | 1400 | 45 | 外推 → 6.2e4 步，×1.4（显存与时间上限） |

**代价与口径**：主网格不再"等步数"，因此**数据塌缩图（M vs E/N^γ）只用等步数那 5 条曲线画**；深度档只用于**律拟合**（M(N,E) 的曲面覆盖），两者在 `metrics_long.csv` 里靠 epoch 数区分，图注必须写明。

**不改的东西**：τ 的校准口径、编码器（dinov2_s）、EMA、检出限删失处理、预声明的选型判据（AICc → 留一 N R² → 参数可解释）全部不变。这是**采样设计**的修订，不是判据的修订。

## 9. 设计修订 R2：主线分辨率改为 64×64（2026-10-30 18:30）

**触发**：R1 的深度档在 28px 上验证成功（N=2000 从 e650 的 M=0 续跑到 e2250，M 升到 **0.041–0.098**，sim_max 0.85–0.89），说明"大 N 需要更多步数"这个判断是对的，方法链路可用。但 28px 对投 Medical Image Analysis 是硬伤（分辨率影响记忆化强度），因此**主线全部改到 64×64 重跑**。

**数据来源（关键）**：官方 MedMNIST+ 的 64px npz 在 Zenodo，本机不可达（403 / DNS 失败）。改用 HF `dz-osamu/MedMNIST` 的 **224px 原始 jpg 包**，用 `build/get_hf64.py` 按 jsonl 顺序 LANCZOS 缩放到 64×64，写成与官方同键名的 npz。**切分与官方完全一致**（pathmnist：train 89996 / val 10004 / test 7180），标签分布与官方 npz 对照无异常。

**口径与代价**：
- 28px 全部结果归档到 `results/pilot28/`（CSV + 5 个 run json）与 `cache/pilot28/`（样本 + ckpt），**只作为方法验证的 pilot**，不进主结果。
- 等步数预算 `STEP_BUDGET=20000` 不变，所以每个 run 的墙钟时间几乎不变（28px 下 17–25 min，64px 下 ~35 min，多出来的主要是采样：512 张 64px 采样 17.8 s/点 vs 28px 3.5 s）。
- 但**大 N 的深度档变贵**：N=4000 的 1400 epoch 在 64px 下约 2 h（28px 下 57 min）。因此深度档改为 N∈{1000,2000} 优先，N=4000 视剩余时间决定。
- `data.ensure_dataset` 不再静默回落到 Zenodo：64px 缺文件时直接报"请先跑 build/get_hf64.py"。

**不变的东西**：τ 的 FPR 校准口径、编码器 dinov2_s、EMA、删失处理、选型判据、停训策略定义。

## 10. 设计修订 R3：候选律扩到五条（幅度衰减 L4/L5）+ 留一 N 改池化口径（2026-10-31 02:5x）

**触发**：deep 档补完大 N 预算之后，L1/L2/L3 的天花板暴露了 —— 它们都假设"平台高度 M∞ 与 N 无关"，而实测平台是 **0.80 / 0.40 / 0.07 / ≤0.01 / ≤0.02**（N=250/500/1000/2000/4000），随 N 陡降。模型在大 N 处系统性高估记忆率，留一 N（把某一档 N 整个留出）因此必然崩（折内 R² 到 −21，池化也过不了 0.8）。

**修订内容（在 cross 数据集与 seed2 出结果之前记录，避免事后挑好看的）**：
1. 新增两条候选律，与 L1/L2/L3 同台 AICc 竞争，选型判据不变：
   - `L4_amp_decay`：`M = A0·(N/250)^(-α)·[1 - exp(-(E/E50)^β)]`，`E50 = E50_0·(N/250)^γ`（5 参）
   - `L5_amp_decay_only`：同式但 `γ ≡ 0`（4 参，时间尺度与 N 无关的零假设）
   - **参数以 N0=250 为参考点锚定**：初版写成 `E50 = c·N^γ` 时 c 与 γ 强相关，优化器会跑到 c=1e5（上界）、γ=−0.67 的角落，参数不可解释。锚定后 `A0`/`E50_0` 直接读作"N=250 时的平台与半升轮次"。
2. **留一 N 的评价口径改为池化 R²**：折内 R² 在"几乎全 M=0"的留出折上没有意义（分母方差≈0，R² 会被放大成 −21 乃至 −1e6 这种量级，纯属除法假象）。池化 R² = 把所有留出折的观测点拼起来算一个 R²，另单独报 `censored_compliance`（M=0 的点是否被模型判在检出限以下）。预声明阈值仍是 0.8，**不因口径变化而放宽**。
3. 顺手修了 `fit_one`/`loo_by_n` 的多起点 bug：原来写死 `p0[3] = gamma 扫描值`，对 L4/L5 等于把 E50 钉死在 0.3–1.5；改为**按参数名**生成多起点（`_p0s`）。

**结果（pathmnist seed1，229 个点，5 档 N，deep 档已补）**：

| 律 | R²_log | R²_lin | AICc | 留一池化 | 删失合规 |
|---|---|---|---|---|---|
| L1_stretched_exp | 0.785 | 0.708 | −459.6 | 0.450 | 0.49 |
| L2_hill | 0.778 | 0.627 | −452.7 | 0.426 | 0.49 |
| L3_two_timescale | 0.744 | 0.597 | −405.7 | 0.072 | 0.32 |
| **L4_amp_decay** | **0.834** | **0.896** | **−539.7** | **0.572** | **0.77** |
| L5_amp_decay_only | 0.789 | 0.751 | −464.6 | 0.464 | 0.49 |

→ AICc 与留一池化一致选 **L4**；`α = 2.06`（平台 ∝ N^−2.06），`γ = −0.69`（epoch 坐标；换算到**优化步**坐标 `t50 ∝ N^(γ+1) = N^0.31`）。

**诚实结论（必须写进论文，不许含糊）**：
- 样本内线性 R²=0.896（≈0.9 达标），但对数 R²=0.834；**留一 N 池化 0.572 < 预声明的 0.8，外推到没测过的 N 不可靠**。
- 原因不是律形式（`build/probe_law_variants.py` 试过 6 种形式，全部卡在 LOO ≈ 0.3–0.57），而是**可测范围只覆盖 N ≤ 1000**：N≥2000 的 M 基本在检出限以下（512 样本 → 检出限 3/512 = 0.006），这些点只能当删失数据用，无法约束律的形状。
- 因此论文的主结论应表述为"在可测范围（N ≤ 1000）内控制律成立、并给出安全窗口的定量形状"，而不是"外推到任意 N"；E* 表在 N≥2000 处输出 `nan` 本身就是结论（**这些 N 在任意训练时长下都到不了 ε**）。
- 阈值稳健性（`build/probe_threshold_law.py` → `results/threshold_law.csv`）：固定阈值 0.5/0.6/0.7 下 `γ_steps = +0.20/+0.36/+0.45`、`α = 1.4/2.1/2.6`，方向一致；阈值 ≥0.8 时只有 2–3 档 N 有信号，参数不可辨识（α 撞边界），故只作参考。**结论不是靠调阈值调出来的**。

## 11. 设计修订 R4：把"开环律早停"真的接进训练循环

**动机**：`controller.py` 里的策略 C/D 是**离线回放**（拿已有测量点判断该停在哪），评审完全可以问"你们的控制器到底跑没跑过"。所以 `train.py` 增加 `--stop-law`：

- 训练开始前从 `results/law_fit.json` 读选定律，反解 `E*(N, eps)`（`law.solve_E_star`）；
- 训练到第 `ceil(E*)` 轮自动停，并在停点存 ckpt + 采样 + 写日志 `开环律早停（L4_amp_decay eps=0.01 E*=612）：E* 已到，停止训练`；
- run JSON 记 `stop_rule` / `stop_epoch_law` / `stopped_early_at`，审计链完整；
- 若该 N 永远到不了 eps（大 N 档），打印"数据本身安全"并继续按预算跑。

**验证计划**（`tools.night_queue --plan ctl`，新 seed 4，避免覆盖主网格 seed 1）：

- `pathmnist_n250_s4`：预算 5125 轮，实际应在 612 轮停（省 88%）；
- `pathmnist_n1000_s4`：预算 2400 轮，实际应在 649 轮停；
- 对照：seed 1 的满预算曲线（同 N 同分辨率），比较停点 M、FID 与后续增长。

**口径**：seed 4 vs seed 1 属跨 seed 比较，需说明；seed 2/3 的全网格跑完后可用 seed 间标准差给出不确定性。

## 12. 设计修订 R5：复现只做可测档；主律与跨数据集律分开拟合

**R5a — seed 3 只复现 N ≤ 1000**（`tools.night_queue --plan replicate_small`）。

触发：seed 1 的横轴上，N=2000/4000 在全预算（9.0 万、8.75 万优化步）内末点 M 只有 0.006 / 0.002，即每 512 张生成图里 1–3 张勉强越线 —— 这些点**在拟合里只作为删失观测**（上限约束），不提供曲线形状信息。对它们再做 seed 3 复现要额外约 5 h 墙钟，换来的只是"删失点的删失更确定"。
判断：seed 间方差只在**有信号**的档位上有意义，所以 seed 3 只跑 N ∈ {250, 500, 1000}（合计约 2.5 h），大 N 档的 seed 方差用 seed 2 单独报告，并明写"大 N 档只做了 2 个 seed"。
代价与披露：这是**有意的样本量不均衡**，论文表格里必须标出每个 (N, seed) 的实际组合数（`results/grid_summary.csv` 里逐行可见）。

**R5b — 主律只用 pathmnist 拟合，跨数据集单独检验**。

原因：cross 的 bloodmnist / pneumoniamnist 每套只有 N ∈ {250, 1000} 两档，5 个参数在这种覆盖下不可辨识（`tools.transfer.py` 冒烟时 A0 直接撞上界 1.0）。若把它们混进主拟合，会让"函数族"的估计被两档数据的局部形状带偏。
做法：
- `python -m law --dataset pathmnist --out results/law_fit.json` → 主律（`build/finalize.py` 已固定这一条，且仍写 `law_fit.json`，因为 `controller.py` / `tools/safety.py` / `train.py --stop-law` 都读这个文件名）；
- `python -m tools.transfer` → 对每个数据集：①固定 pathmnist 的 α/β/γ、只重估 A0 与 E50（`transfer` 行）；②五参全放开（`free_fit` 行，上限对照）。

首批结果（bloodmnist, seed 1）：
| mode | R²_log | R²_lin | α | γ | E50@250 |
|---|---|---|---|---|---|
| transfer（固定形状） | 0.534 | 0.832 | 2.056（固定） | −0.689（固定） | — |
| **free_fit（自由拟合）** | **0.984** | **0.962** | **0.78** | **−0.31** | 1806 |

→ **函数族可迁移，参数不可迁移**。这正好支撑两个落地结论：医院换数据域时必须用自己的少量 run 重新标定（而不是照抄论文里的 E\*），或者干脆用不依赖律形状的**闭环**控制器（策略 D，在线测 M 再停）。cross 的 onset 步数斜率（log-log）也差一倍：bloodmnist 0.66、pathmnist 1.29。

## 13. 设计修订 R6：安全早停表改成"最差 seed + 假阳性地板"口径

**触发**：用 seed 4 真跑 `--stop-law`，律给 E*=612 并在 e612 停，实测该点 M=0.0273（14/512）> ε=0.01 —— 违约。
查 seed 方差：pathmnist N=250 在 e640 三个 seed 的 M = 0.0020 / 0.0332 / 0.0566，**发作时间差约 20 倍**。
律是按均值拟合的确定性时刻表，单条轨迹上无法保证 M ≤ ε。

**修订 1（口径）**：`safe_early_stop.csv` 的 `M_stop` 取**所有 seed 里最差的一条**，`ok` 要求最差 seed 也 ≤ ε；
同时给出经验保守停点 `E_star_emp`（每个 seed 发作前的最后一个测量点，取所有 seed 的最小值）与 `ok_emp`。
`recommended` 要求 `ok and ok_emp and ok_quality`。

**修订 2（地板）**：τ 按 FPR=0.5% 校准，所以"一个都没记住"时也有约 0.5% 的生成样本越线。
ε ≤ 2×FPR 的档位（0.005、0.010）标为 `informative=False`，不给交付结论；可交付档位从 ε=0.02 起。

**修订 3（干预组不计入观察）**：`law.load_metrics` 剔除 `results/runs/*.json` 里带 `stop_rule` 的 run，
否则 ctl run 只在自己的停点前有数据，会被当成"最差 seed"自我循环。

**结论（写进交付物的话）**：
- 可交付点（seed1 三档数据、律 L4 重拟合后）：pathmnist **N=1000, ε=0.02**，E*=603，实停 e600/2400（省 75%），M=0，FID 231 vs 211（1.10×）。
- 小 N（250/500）上"又安全又好看"不存在：早停能压住 M，但 FID 是跑满时的 2–3 倍。
- 因此论文的核心论点要从"给一个公式"升级为"公式 + 闭环兜底"：固定时刻表会因种子方差在个别轨迹上违约，
  在线测 M 再停（C2）不是锦上添花而是必需。

## 14. 设计修订 R7：拟合口径的最后两个决定（种子均值 + 可测区间 R²）

**R7a 拟合目标改成种子均值曲线**：M(N,E) 是**期望记忆率**，seed 间差异是噪声。
`law.collapse_seeds` 把同一 (dataset, N, epoch) 的多个 seed 折成一条均值曲线再拟合（`--per-seed` 可关）。
代价：报告的数字从"单 seed 拟合"（R²_lin 0.896）变成"多种子均值拟合"（R²_lin 0.832 / R²_log 0.765），
但后者才是可复现的口径 —— 单 seed 的 0.9 有运气成分（那个 seed 的曲线恰好最"标准"）。

**R7b 增加"可测区间 R²"**：只在 M ≥ `MEAS_FLOOR=0.02`（4 倍假阳性地板）的点上算 `r2_log_meas / r2_lin_meas`。
动机：检出限附近（M≈0.004）的点相对误差天然巨大，把它们算进 R² 会让"律在可测区域有多好"看不出来。
结果反而显示 L4 在可测区间的 R² 只有 0.67 —— **误差集中在真正有信号的区域**，不是在噪声区。这点必须写进结果。

**试探过的第七个候选（未采纳）**：让形状参数随 N 变（`β = β0·(N/250)^δ`，6 参数）。
`build/probe_beta_n.py` 实测：R²_log 0.8397 / R²_lin 0.8372 / AICc −579.8 / LOO池化 0.496 ——
比 L4 好，但 `β0` 撞上界 8.0、`δ=−1.10`，参数不可辨识，且 R² 仍到不了 0.9。
**不采纳**：按预声明判据（参数可解释）它不合格；留在 `build/probe_beta_n.py` 作为"测过并被否"的记录。

**结论（写进论文的口径）**：
- 预声明的 R²≥0.9 在多种子严格口径下**没有达成**（R²_lin 0.848、R²_log 0.756；逐 run 口径 0.788 / 0.799）。
- 可解释的结论仍然是立得住的：`α≈1.97`（平台高度 ∝ N^-2）、`γ≈-0.69`（epoch 坐标；步数坐标 τ ∝ N^0.31）、
  以及"数据量翻倍，安全窗口非线性变宽"这一条定性结论在 5 档 N 上单调成立。
- 残差结构（逐档 bias 0.42–1.72）说明单一 β 撑不起 5 档曲线的形状差异，这是**数据覆盖与函数族的联合限制**，
  不是拟合方法的问题（6 种形式 + 未删失重拟合 + 幅度衰减都试过）。

## §15 设计修订 R8（收官前的三处修正，2026-10-31 晚）

省 64% 轮次、M_停 0.0025、违规率 **0%**。

R8b **审计豁免干预组**。`tools/audit.py` 的"每个 run 至少 8 个测量点"对 `plan ctl` 的早停 run 不成立

## §17 设计修订 R9（2026-11-01：加密网格 + 补 seed + 真闭环）

**动机**：R7 之后留一 N 仍只有 0.473，唯一合法的改进路径是补数据（不是换口径）：
加密 N 网格可能让"外推到没测过的 N"变成"内插"；补 seed 能检验最差 seed 口径是否只是 3 个 seed 的偶然。

**新增实验（全部 2026-10-31 19:36 – 11-01 03:36 完成，共 8 h）**：

| plan | 内容 | 目的 |
|---|---|---|
| `dense` | pathmnist N∈{1500, 3000} × seed∈{1,2}，等步数 20000 步 | 把 250–4000 之间的空档填上，检验律的形状是不是被稀疏网格误导 |
| `seeds56` | pathmnist N∈{250,500,1000} × seed∈{5,6} | N≤1000 从 3 个 seed 增至 5 个，给"最差 seed"口径统计意义 |
| `ctl_online` | seed 7，N∈{250,500,1000}，`--stop-eps 0.02` | 闭环控制器**第一次真跑**（此前只在离线 CSV 上回放） |
| `fpr_sens` | τ 的 FPR 取 0.1%/0.5%/1% | 证明记忆率不依赖度量的自由参数 |

**预声明**（先写后看结果）：① 若留一池化 R² 仍 <0.8，则认定"律的预测力有天花板"，并把主交付物改成闭环控制器；② 闭环若在 ε=0.02 下违规率 >0，则说明 eps 需再抬高或度量需更灵敏；③ 加密网格若让 R² **下降**，不得改口径或删数据点，只能如实报告。

**结果与判读**：

1. **R² 确实下降了**（R²_log 0.756→0.709、R²_lin 0.848→0.774、留一 0.473→0.442）。按预声明，如实报告，并去查原因。
2. **原因查到了**：同一 N 下不同 seed 的发作步数相差最多 8 倍（N=1000：2344/4688/12891/15234/18750 步）。子集方差 > N 的系统位移。这不是"模型选错"（六种律形式都到不了 0.9），而是**记忆化本身在给定 (N,E) 处有巨大 run-to-run 波动**。
3. **闭环真跑结果符合预期**：seed 7 三个 N 分别在 e800 / e640 / e750 触发（ε=0.02），交付 e640 / e560 / e675，全部合规。
4. **FPR 敏感性**：10 倍 FPR 变化 → M 只动 4 个百分点（n250：0.773 → 0.805 → 0.840）。结论不依赖 FPR 取值。

**由此确定的主线叙事**（写论文按这个来）：

> 固定时刻表（律）只能给出**期望**停点，实测违规率 18%；FID 平台早停（工业界最常见的做法）违规率 75%，因为它等的是"画质不再涨"，而记忆化早在那之前就开始了。
> 想在隐私预算内安全早停，必须**边训边测**：闭环控制器 28 个 run 全合规，同时省掉 59% 的训练轮次。
> 律的价值因此不是"免测量"，而是①给闭环一个先验停点上界，②解释"为什么数据越多越安全"（α≈2 的幅度衰减）。

**这也修正了 §16 的定位**：§16 的数字保留作对照（5 档 N、3 seed 口径），正式报告一律用 R9 之后的 7 档 N、多 seed 口径。

## §20 设计修订 R12（2026-11-01 夜：B 组三个实验的预声明与判读规则）

### B10 换编码器重算（度量稳健性）
- 设计：同一批生成样本、不重训练，编码器 DINOv2 ViT-S/14（384 维）→ ResNet50（2048 维），τ 逐 N 按同一 FPR=0.5% 重校准。4 个 run（N=250/500/1000/1500）。
- 预声明判据：①M(E) 曲线 Spearman ρ ≥ 0.9；②末点 M 绝对差 ≤ 0.05；③平台随 N 的单调性在两种编码器下都成立。
- **结果**：③通过；①②在 N=1500 上不通过（ρ 0.836、末点差 0.105），N=250/500/1000 基本通过（ρ 0.96–0.99）。

  ⇒ α 报成"条件指数"，必须与编码器 + FPR 口径一起报；跨论文比较 α 无效。
- 诚实记录：N=1500 是 4 张 vs 34 张图的差距，属"地板附近的计数差"，不据此宣称哪个编码器"更对"。

### B9 224px 分辨率 pilot（分辨率敏感性）
- 设计：pneumoniamnist、N=1000、seed=1、batch=16、**8000 优化步**（主网格的 40%）、8 个测量点、每点 256 张样本；输出隔离到 `results/pilot224_metrics.csv`。
- 为什么降步数：8 GB 显存在 224px 只能 batch 16，2 h 预算内跑不了 20000 步。
- 预声明判据：**只回答定性问题**——"224px 上记忆化是否仍然出现（末点 M 明显 > 0）"，
  以及"onset 是否仍晚于生成质量改善的开始"。**不比较绝对 M 与 FID**（跨分辨率不可比，见 28px 附录的同类结论）。
- 若末点 M 仍接近 0：只能写"在 40% 预算内未出现"，不能写"224px 不记忆化"。

### B11 补 seed 8/9（seed 方差与可交付安全余量）
- 设计：pathmnist × N∈{250,500,1000} × seed∈{8,9}，预算同 FINAL（5125/2550/2400），
  加上已有 seed 1/2/3/5/6，可测三档各有 7 个 seed。
- 目的：①把"最差 seed 违约"的概率估成可交付的数，而不是靠 3 个 seed 的运气；
  ②给出**带方差的早停建议**：`E*_safe(N,ε) = E*_law(N,ε) − k·σ_onset(N)`（k=2），
  并报"该口径下 7 个 seed 全部合规的比例"。
- 预声明判据：若 `E*_safe` 在 N≤1000 的任一档上能让 7/7 个 seed 全部合规且省 ≥30%，
  则"开环律 + seed 余量"可作为**不需要在线测量**的廉价方案写进论文（与闭环并列成为两个交付形态）；
  否则论文只能主张闭环。
- 诚实记录：seed 方差本身（σ_onset）是结论的一部分，不是噪声——它决定"固定时刻表"的可信区间宽度。

## §21 设计修订 R13（2026-11-02：B11 的 seed 余量结果 + 三种交付形态并列）

- **触发**：seed 8/9 补齐后，可测三档各有 7–9 个 seed（`metrics_long.csv` 1266 行 / 34 个 run），
  于是"最差 seed 违约概率"第一次可以当成可交付的量来报，而不是靠 3 个 seed 的运气。
- **口径**（`build/seed_margin.py` → `results/seed_margin.csv`）：
  `E*_safe(N,ε) = E*_law(N,ε) · 10^(−k·σ_log(N))`，`k=2`，`σ_log = std(log10 onset_steps)`；
  判据是**在该停点上所有 seed 的 M 都 ≤ ε**（不是平均）。
- **结果（ε=0.01）**：

  | N | seed 数 | σ_log | E*_law | E*_safe | 省轮（safe） | M@law | M@safe | 质量代价（FID 比） |
  |---|---|---|---|---|---|---|---|---|
  | 250 | 9 | 0.052 | 389 | 306 | 94% | 0.000 | 0.000 | 2.54× |
  | 500 | 8 | 0.056 | 390 | 301 | 88% | 0.000 | 0.000 | 1.80× |
  | 1000 | 9 | 0.341 | 407 | 85 | 93% | **0.068（违约）** | 0.000 | 1.55× |
  | 1500 | 2 | 0.000 | 453 | 453 | 47% | 0.008 | 0.008 | 0.84× |

  **"开环律 + 2σ 余量"可以作为不需要在线测量的廉价交付形态**，与闭环并列写进论文。
- **但代价必须同时写**：该形态下 FID 是跑满的 1.55–2.54 倍（省掉的轮次正是质量还在快速改善的区间），
  而闭环在 34 个 run 上省 66.6%、违规 0%，FID 代价小得多。
- **新发现（另见 `docs/NOTES.md` §13）**：σ_log 随 N 变大（250/500 ≈ 0.05，N=1000 达 0.34）。
  即"数据越多、平台越低"，但"什么时候开始记"反而更不稳；固定时刻表的可信区间随 N 变宽，
  这从另一个角度支持闭环。
- **帕累托阶梯（论文里就按这个顺序讲）**：
  闭环（省 64–67%、0 违规、质量代价小）> 开环+2σ（省 88–94%、0 违规、质量 1.5–2.5×）
  > 开环无余量（省 61–65%、违规 11.8%）> FID 早停（省 24%、违规 79.4%）。
- **交付口径不变**：`safe_early_stop.csv` 仍是"最差 seed + 假阳性地板 + 质量"四条件严格口径，
  `recommended` 列 28 行全为 N——三种形态并列讲，不等于放宽验收线。

## §22 设计修订 R14（2026-11-02 02:2x：224px pilot 的测量密度下调）

**触发**：B9（224px 分辨率 pilot）按 R12 的预声明是 8 个测量点 × 256 张采样。
实测第一个采样点用了 45 min 还没出图（GPU 被功耗墙压在 225 MHz；train.py 的 DDIM 采样
是**整批一次生成**，256 张 224px 在 8 GB 卡上单次前向极慢），整条 8 点预计 7 h 以上。

**决定**：把 B9 降为 **4 个测量点（ckpt-every 32）× 128 张采样**（量化步长 0.78%，主网格是 0.20%）。

**为什么可以降**：224px pilot 是正文 §5.6 "分辨率敏感性"的旁证，只回答
"224px 下是否仍然发生记忆化、量级是否同阶"，**不参与任何拟合**（律只在 64px 上拟合），
也不需要 onset 斜率。降密度牺牲的只是曲线的细粒度，不影响它要支撑的那句话。

**代价与写法**：论文里必须写清"224px pilot: 4 个测量点、128 张/点（量化 0.78%）、8,000 步，
仅用于定性对照，不用于估计斜率或指数"。**不允许**把它和主网格的 onset 斜率放在同一张表里比。

**顺带记录**：B9 第一次失败是 run tag 复用（`pneumoniamnist_n1000_s1` 与 64px cross 同名 →
train 判"续跑到 2400 轮"，6 s 结束并覆写 json），已改用 seed 21；这是"pilot 必须用全新 tag"的实例。

**更正（2026-11-02 03:1x）**：上面把慢归因于"224px 采样本身贵"是**错的**。事后基准
（`build/bench_sample224.py`）显示 224px 采 128 张只需 ~45 s（batch 2–16 都是 0.14 s/张、峰值 ≤1.4 GB）。
真实原因是**同一个 pilot 被启动了两份**（`build/queue_b9.log` 那次与手动那次各留了
一个 `build.pilot224` + 一个 `train` 子进程），两个进程同时占 8 GB 显存 → 驱动退回共享显存换页，
GPU 100% 利用率但只有 29 W、225 MHz，单步慢 70 倍。处置：杀干净全部 python、确认 0 进程后重起一份。
**教训（第 4 条同类）**：跑长任务前必须 `Get-Process python | Measure-Object` 确认没有孤儿进程；
"看起来在算但极慢"要先用 nvidia-smi 的功率/时钟判断是不是换页，而不是先怀疑算法。
4 点 × 128 张的密度决定**保留**（仍然受 8 GB 与时间的双重限制，且 pilot 只需要定性对照）。

## §23 设计修订 R15（2026-11-02 03:5x：224px pilot 延长到 30k 步）

**触发（先记录、后出结果）**：R14 定的 4 点 × 128 张、128 epoch（=8,000 步）跑完了，
结果是 `M=0`（4 个点全 0）、`sim_max ≈ 0.25`、FID 472→315、**每张图像素 std 只有 12（均值 126）**——
采样出来的是**无纹理的均值图**（`figs/probe224_samples.png`）。也就是说 8,000 步在 224px 上
还没进入"能生成像样图像"的阶段，此时 `M=0` 不能解释为"224px 不记忆"，只能解释为"还没学会生成"。

**决定**：延长到 **480 epoch = 30,000 步**（8 个测量点 e64…e480，每点仍 128 张）。
按实测 16.5 s/epoch 约 2.2 h。**在跑之前登记**：这次的结果才是"分辨率敏感性"的判据。

**判据（现在写死）**：
1. 若末点 `M ≥ 0.05`（≥7/128）且 FID 相对同预算 64px 同量级 → 说明"224px 下仍会记忆化"，
   支持"分辨率不改变定性结论"；同时报告平台与 onset 的绝对差异（不做拟合，只报两点）。
2. 若末点 `M ≈ 0` 且像素 std 仍 <20（仍是均值图）→ **判 pilot 失败**，不写进正文结论，
   只在 limitation 里写"224px 需要 ≥ 数万步且需要重新调 batch/LR，本轮机器时间不够"。
3. 无论哪种，都**不**把 224px 的 onset 与 64px 的 onset 放同一张表比较（量化步长 0.78% vs 0.20%）。

**已登记的偏差**：batch 16（vs 主网格 64）、LR 仍 2e-4（未按 batch 调）、DDIM 50 步、EMA 0.999 不变。

**R15 结果（05:18 收工，480 ep = 30,000 步，8 点 × 128 张）**：
| 指标 | e192 | e320 | e480 |
|---|---|---|---|
| M | 0 | 0 | **0** |
| sim_max | 0.243 | 0.272 | 0.244 |
| tau | 0.3524 | 0.3524 | 0.3524 |
| FID | 121.7 | 110.2 | 116.7 |
| 每图像素 std | 18.8 | 26.3 | **30.8** |

**判定：inconclusive（按 §23 预先写死的判据，落在第 1、2 条之外）**。
理由：(a) `M=0` 且 `sim_max`(0.24–0.27) 一直**低于** τ(0.352)，即在"最靠边的那个方向"上都没碰到训练集；
(b) 但生成保真度仍未达标（FID ~110–120、像素 std 30.8，仍比真实图平滑），
所以**无法把"不记忆"与"还没逼真到会复刻"分开**；(c) 另有 batch 16（主网格 64）这个混杂因素（小 batch 梯度噪声更大）。

**结论口径（写进论文 limitation，不进正文结论）**：
"224px/30k 步的单配置 pilot 未检出记忆化，但该配置的生成保真度不足以支持'分辨率不改变记忆化'的断言；
480 epoch 之后 FID 仍在下降、std 仍在上升，说明它还没进入可测区。"
`sim_max` 随 FID 改善而**下降**（0.267→0.244）也和"记忆化应该随保真度上升而增加"相反，
提示这一路更像"特征空间里生成的图还不够锐"而不是"真的没背"。

## §24 设计修订 R16 —— 判据对齐（原文 Eq.6）与 onset 斜率更正

**触发**：审阅"我们是否复现了 τ_mem ∝ N"时发现两件事都建在二手描述上：
(a) 我们从未核对 Bonnaire et al. 的**记忆化判据**本身；(b) 我们报的 onset 斜率 +0.64
把 N≥1500 那几档"1–3 张图偶然越线"也算成了起跳点。

**核对结果（原文 §2 "Evaluation metrics"，`build/bonnaire.txt`）**：他们的判据是 Eq.(6)

```
E[ ||x − a_μ1||₂ / ||x − a_μ2||₂ ] < k,   k = 1/3
```

`a_μ1 / a_μ2` = 训练集内**像素 L2** 的最近 / 次近样本。原文注：k 取 1/2 或 1/4 不改变 scaling 结论。

**据此的三项动作**：

1. **独立实现该判据**：`build/eq6.py`（像素 L2、k=1/3、topk=2）→ `results/eq6.csv`。
   复算我们四个档：

   | run | N | 我们的 M（特征余弦） | 原文 f_mem（像素比） |
   |---|---|---|---|
   | bloodmnist_n250_s1@e5125 | 250 | 0.971 | 0.672 |
   | pathmnist_n250_s1@e5125 | 250 | 0.805 | 0.412 |
   | pathmnist_n1000_s1@e2400 | 1000 | 0.066 | 0.014 |
   | pneumoniamnist_n64_s31@e2000 | 64 | 0.000 | 0.008 |

   排序一致；幅度上像素比判据约严 2×。**保留我们的 M 作为主指标**（特征空间对"语义近邻"更敏感，
   且 τ 有显式的 FPR 含义），Eq.(6) 作为**可跨论文比的旁证**。

2. **更正 onset 斜率**：斜率只在"平台 ≥ 5%（≈25/512）"的档上拟合（`tools/plot.py` 的 `CRED_MIN`）。
   结果：`onset/N` = 11.07 / 10.63 / 10.40 步/张（N=250/500/1000）→ **斜率 0.95 ≈ 线性**（ε=5% 时 1.28）。
   此前报的 +0.64 作废（那是把量化噪声当起跳算出来的）。

3. **与原文的关系改写**：从"未复现、明确不声称"改为
   "**结构复现（线性），常数不同（≈10.5 vs ≈300 步/张），判据不同（特征余弦 vs 像素比）**；
   原文明说 `f_mem(τ_max)` 的终值随 n 变但未给标度，我们的 `A(N) ∝ N^-1.9` 是把这条定性定量化"。

**新增验收条目**：
- 任何跨论文的"斜率/指数"比较，必须写明（i）判据、（ii）时间单位、（iii）参与拟合的档位及其可测性；
- 斜率拟合必须显式排除"平台低于 5%"的档（`CRED_MIN`），并在图注里说明（空心点）。

### §24.5 R17 分辨率判据实验：等步数是错的口径

**触发**：B9（pneumoniamnist 224px）跑出 `M=0` 但无法判读——它的参照集只有 624 张，且该实验曾被两份进程抢卡污染。
要一个能判读的分辨率对照，必须选 64px 下信号最强的档：bloodmnist N=250（64px 平台 0.9707）。

**预声明**：224px、bloodmnist、N∈{250, 1000}、seed 21、batch 16（8 GB 显存只放得下这么多）、
每点 128 张采样、**步数预算 25,000**（与 64px 主网格的 20,000 步同量级，当时当作"等量"）。

**结果（N=250：25,000 步 = 1,600 轮，107.6 min）**：`τ=0.4787`（参照 2000、去泄漏 0），8 个检查点
**M 全为 0.0000**、`sim_max` 0.315–0.365、FID 371.0 → 208.9（仍在稳定改善，不是训练失败）。

**判读（这是我自己的设计错）**：**等步数 ≠ 等重复次数**。记忆化由"同一张图被看多少遍"驱动，
batch 从 64 降到 16 让 25k 步对应的 epoch 从 5,125 掉到 1,600（3.2×）。
所以 224px 的 `M=0` **不能**读成"高分辨率不记忆"，只能读成"在 1,600 轮时还没到那个重复次数"。

**改为等 epoch 口径后的结论**：同为 **E=1,600** 时，64px 已 `M=0.375, sim_max=0.787`，
224px 仍 `M=0.000, sim_max≈0.35` → **分辨率至少把 onset 推到 1,600 轮之后**（N=250、13 M 参数、同一 τ 口径）。
224px 自己的平台仍未测到，需续训到 E=6,400 才能回答"平台降不降"。

**新增验收条目**：跨分辨率/跨 batch 的比较必须**按 epoch（每图重复次数）对齐**并同时报出 batch；
禁止用"等步数"充当可比性声明。凡因显存压缩了 batch 的实验，判读前先把 epoch 换算回来。

### 24.6 R18 下界探针 N=128/192（事后登记，含"不进主拟合"的处置）

- **动机**：`docs/COMPARISON.md` §2.4 里"onset 步数 ≈ 10·N"只在 N≥250 上有数据；补 N=128/192 是为了
  把这条经验常数的适用下界往外推。
- **预声明**：N=128 与 192 各 1 个 seed、20,000 等步数预算；检查点 1250/825 轮；

- **结果**：两档首个检查点即越线（M=0.074 / 0.018），M_max 0.990 / 0.873 → 只能给
  onset 上界 ≤19.5 / ≤12.9（步每图）。
- **判读（不改口径）**：①方向确认（平台随 N 单调下降，相差 128→250 就有 0.99→0.68）；
  ②**不能**用来定 onset 常数，因为白化维数 k=max(32,min(d,N/2)) 在这两档是 64/96（主网格 125/384），

- **新增验收条目**：任何"补一档数据"的动作，必须先声明它进不进主拟合、依据是什么；
  若不进，必须在 CI 之外的地方写下过滤常量（这里是 `config.FIT_MIN_N`），不能靠"记得别加进去"。

### 24.7 R19 224px 续训（事后登记：判据是"6,400 轮仍为 0 就停，不再加预算"）

- **预声明（在续训启动前写定）**：同一子集同 seed（bloodmnist N=250 seed=21）把 224px 训练从 1,600 轮续到
  6,400 轮（每 200 轮一个测量点）。判据：若 6,400 轮内首次越线 → 报 224px 的 onset；
  若仍为 0 → **结论限定为"onset 在 6,400 轮之外"**，且**不再为 224px 加预算**（22 h/档，收益递减）。
- **结果**：6,400 轮内 M 全程 0（32 个点）；`sim_max` 0.315→0.446（最高点在 e6400），τ=0.4787；
  FID 371→218 后走平 → 走"仍为 0"这一支。
- **判读**：见 `docs/NOTES.md` §18 三条：onset 至少推后 8 倍；`sim_max` 缓慢上移所以只能说"未达可检出复刻"、
  不能说"不记忆"；分辨率与 batch 不可解耦，必须进 limitation。
- **新增验收条目**：跨分辨率/跨 batch 的对比必须同时报**分辨率、batch、每 epoch 步数**三个量；
  只报步数或只报轮数的对比一律视为口径不完整。
